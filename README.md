# SuperWY Fabric（机器人 0.6.7 / 玩家取货端 0.6.2）

使用手册：https://xiaodoumedia.feishu.cn/wiki/OkcowvPLTiqiGBkgtKzcB9RJnXg?from=from_copylink

两个独立的 Minecraft 26.1.2 Fabric 客户端 mod：

- **机器人端**：[superwy-fabric](superwy-fabric/README.md)，轻量 Web 控制（历史列表最多 10 条）、私聊接单（可选 5 位短 key）、多区域独立控制与持久断点扫描、后台库存解码和索引查询、容器黄标与未扫描坐标、多人 FIFO 排队、异常立即停止与普通聊天缺货提示、按缓存取物及 GCA 假人背包原地散装交付；共享玩家控制，支持自由转向、手动移动及失焦后台寻路；快捷栏保留，已有背包物品不移动。
- **玩家取货端**：[superwy-requester](superwy-requester/README.md)，游戏内配置和原版按键绑定，默认私聊下单、可切换 HTTP；未提交清单支持聊天栏点击删除与取消，执行和排队仅显示单行状态，超背包清单自动装盒、分批交付并实时回报进度。

另提供独立的 [Baritone 转向补丁](baritone-steering-fix/README.md)，用于 Minecraft 26.1.2 / Baritone API 1.18.0 原生 `#goto` 的旋转执行，不依赖机器人端或玩家取货端。

各项目 `dist/` 中包含独立 jar、源码归档、配置及验证说明。Java 25；机器人端要求 Fabric Loader ≥0.19.5、Fabric API ≥0.155.3，玩家取货端保留两项依赖但不限制版本。

0.6.7（仅机器人端）：游戏内 `/superwy web` 生成带令牌的本机管理链接，点击即自动登录网页。

0.6.6（仅机器人端）：网页新增“缺货对比”页，上传 Litematica 材料列表 JSON，重新扫描全部仓库后只列出仓库不够的物品中文名和缺少数量。

0.6.5（仅机器人端）：装盒改为打开一次、依次放入、关上后一次核对，速度更快；用完箱子后的缓存刷新失败不再打断任务。

0.6.4（仅机器人端）：背包空格少时不再把只装了一个物品的盒子交出去；没装满的盒子留在身上继续装，装满才召唤假人；空格不够先把非本单物品存进余物箱。

0.6.3（仅机器人端）：取货途中箱子被改动时不再因“需要核对”结束任务，改为扫描机器人背包按实际数量继续；调度任务块因机器人自身问题失败时，未交付部分重新派出。

玩家使用手册（全部功能和指令）见 [玩家取货端使用手册.md](玩家取货端使用手册.md)。

超级调度模式的完整使用说明见 [超级调度模式使用说明.md](超级调度模式使用说明.md)。

0.6.2 / 0.6.2：缺货不再中断任何任务，缺的物品跳过、其余做完；结束时公屏和取货端各汇总一次：哪些完全缺货、哪些缺多少。

0.6.1 / 0.6.1：批量和投影取货开始前先查机器人缓存库存，缺货单独一栏显示，确认（或强制）后才开始；机器人网页新增“超级调度”页（机器人状态、任务管理、设置、调试）；签名密钥由 FRP 凭证派生、重新打包不变；减少内存占用。两端都需要更新。

0.6.0 / 0.6.0：超级调度模式（默认关闭）。多台机器人同时在线时由 tiantian996 排队派活并参与取货，其他机器人自动找到它；单项取货优先、批量按块分派并整单排队，掉线 2 分钟后改派、回来继续。玩家私聊下单彻底停用，玩家端只走 HTTP，机器人开启超级调度后玩家端需 `/swrequest mesh on`。两端都需要更新，所有机器人需使用 private jar。详见各自 README。

0.5.6 / 0.5.0：圈投影取货。Litematica 区域编辑器（M）新增“机器人取货”按钮：统计选区内投影材料并检查背包缺失数量，确认后本地预估需要几个潜影盒、每盒装什么（鼠标悬停查看盒内排布），再下发给机器人，以多个潜影盒交付，收货假人装不下沿用 `_1`、`_2`。两端都需要更新。

0.5.5：补货机换盒或取货界面变化后，等待 1 秒、核实已取数量并重开重试；每次开箱按实际菜单重新定位散装物品、源盒和盒内物品，归还源盒时使用同一容器当前空槽，优先原槽。玩家取货端无需更新。

0.5.4 / 0.4.2：历史订单移至数据库按需读取，扫描解码积压设上限，超时/断线/异常释放缓冲；取货端限制响应大小、并发与跟踪任务数量，响应体传输完整超时后主动取消网络工作，断线释放待处理请求。

0.5.3：每个订单开始取货前自动关闭空光标容器界面；排队请求不打断当前取放，光标有物品时保留现场。

0.5.2：每完成交付 50 轮，将主背包余物存入 `80,50,-23` 的箱子；保留快捷栏、装备和副手，计数重启保留，箱满单独提示并保留余物。玩家取货端无需更新。

0.5.1：普通订单取货过程中缺货时交付已取物品；要求 64 个、取到 54 个，会实际交付 54 个，并在公屏发送 `物品ID 缺货10个，已交付54个`。批量订单也按物品汇总缺货与实交数量。玩家取货端升级至 0.4.1，支持未提交清单点击编辑及单行执行/排队状态。

0.5.0 / 0.4.0：清单超过 25 格自动打包；首轮最多 25 格、后续最多 24 格，并按实际空槽预留工作空间。空盒补充点默认 `129,53,-21`，64 堆叠空盒每次只取 1 个。携带 25 盒即交付再继续；收货假人满时依次改用 `_1`、`_2`。任务结束将主背包 27 格余物投至全物品入口（默认 `100,49,0`），保留快捷栏、装备、副手。设置位于网页“仓库区域”。保留混合 FIFO、原版按键、批量异常逐项跳过和实时进度。

保留当前服务器两个末地仓库预设、内置 Windows x64 frpc、本机随机端口及公网端口持久复用。机器人用 `/superwy connect` 复制一条指令，玩家端 0.4.0 在游戏中执行，弹窗填写收货名后保存 HTTP 连接。机器人 `-private.jar` 带所有者的 FRP 认证，仅供自用；普通机器人 jar、源码和玩家 jar 不含此认证。

机器人端和玩家端的测试记录见各自 VERIFICATION.md。远程生产服务器需要按 README 配置地址、玩家令牌及假人允许名单后验收。
